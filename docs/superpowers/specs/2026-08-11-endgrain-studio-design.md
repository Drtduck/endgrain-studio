# Endgrain Studio: design spec

Дата: 11 августа 2026. Автор: Станислав Кузнецов. Статус: принят к реализации.
Конкурс: Вайбатон №1, дедлайн 17 августа 2026. Репозиторий приватный (решение автора), на сдачу уходит live URL, демо-GIF, примеры досок и объяснение, как изготовить доску.

## Цель и критерии успеха

Endgrain Studio - производственный инструмент столяра, а не графический редактор. Пользователь приходит с идеей (или с фотографией) и уходит с проектом, по которому реально можно склеить торцевую разделочную доску: узор, размеры каждой заготовки, схема двух склеек, карта раскроя, расход пиломатериала по породам, отходы, себестоимость и печатная инструкция.

Главный сценарий (hero flow) - photo-first: загрузил фото -> ввёл габариты доски -> получил реализуемый узор, его вариации и мгновенную визуализацию. Это то, что показывается в демо-GIF первым, потому что даёт максимальный wow за 15 секунд и одновременно закрывает бонус «импорт изображения».

Критерии успеха, по которым проект считается сданным:

1. Функциональность. По экспортированному PDF человек с фуганком и торцовочной пилой собирает доску без догадок: указаны толщины, ширины, длины, углы, порядок склеек, припуски и kerf.
2. Удобство для человека, который не писал код. От открытия ссылки до первой готовой доски - меньше 60 секунд без регистрации и без единого поля с техническим жаргоном.
3. Качество и разнообразие генерации. Не менее 12 параметрических шаблонов, 3 симметрийных семейства, эволюция узоров и photo-to-pattern. Два случайных прогона генератора не должны давать визуально одинаковый результат.
4. Техническое качество. Чистое разделение engine/render/export, property-тесты на инварианты изготовимости, зелёный CI, деплой на Vercel с main.
5. Wow. 3D-превью торцевого среза с процедурной текстурой, «Приёмка мастера» и мгновенный share-линк с автогенерируемой OG-картинкой.

Отдельный жёсткий критерий: монетизация не должна мешать судейству. Все Pro-функции открываются переменной окружения `PRO_UNLOCK=1` (в конкурсном деплое она включена) и промо-ссылкой `?unlock=<токен>`, которая кладёт entitlement в localStorage на 30 дней. Судья не увидит ни одного paywall.

Язык интерфейса: русский по умолчанию, переключатель на английский в шапке. Обоснование: конкурс судит русскоязычное сообщество, поэтому родной язык интерфейса снимает трение у жюри, а рынок инструмента международный (Etsy, Printful), поэтому английская локаль нужна. Цена решения низкая: все строки живут в одном словаре `lib/i18n/{ru,en}.ts`, компоненты не содержат литералов. Английский перевод делается один раз в день 6.

## Доменная модель

Все размеры хранятся в миллиметрах как числа с плавающей точкой. Дюймы - исключительно представление на уровне UI и экспорта, конвертация в одном месте (`lib/units`).

- `Species` - порода: id, название (ru/en), цвет в LAB, плотность, цена за кубометр, коэффициент усушки (радиальный и тангенциальный), признак «пищевая безопасность».
- `Strip` - полоса первой склейки: порода, ширина, толщина (высота будущей доски), длина.
- `Panel` - результат первой склейки: упорядоченный список элементов. Элемент - либо `Strip`, либо `SliceRef` (ссылка на другую панель: `panelId`, толщина среза, угол реза). Рекурсия ограничена глубиной 2: панель может ссылаться на панель, но не на панель, которая сама ссылается на панель. Глубины 2 хватает на chevron, herringbone и tumbling blocks. Глубина 3 не поддерживается сознательно и валидатор её блокирует с понятным сообщением.
- `Row` - поперечный срез панели, из которого собирается финальная доска: `panelId`, толщина среза, угол реза, флаг переворота (flip), флаг зеркала (mirror), торцевой припуск (trim).
- `Design` - корневой документ: список пород, список панелей, список рядов, габариты доски, kerf, припуск на строгание, версия схемы.

Доска - это список `Row`, каждый из которых ссылается на панель. Всё остальное выводится, а не хранится. Из `Design` детерминированно вычисляются: длина каждой панели (сумма толщин срезов + kerf × (n − 1) + trim), потребность в пиломатериале по породам, отходы, себестоимость, число склеек и число резов. Дублирующих полей в модели нет, поэтому рассинхрон невозможен по конструкции.

Функция `compile(Design) -> BoardModel` - единственный источник геометрии. `BoardModel` содержит плоский список ячеек с абсолютными координатами, цветом породы, направлением волокна и происхождением (какая панель, какой ряд, какая полоса). На этой структуре работают все рендеры, калькуляторы и экспортёры.

## Архитектура и стек

Next.js 15 (App Router) + TypeScript + React 19, деплой на Vercel. Состояние - Zustand + immer, undo/redo через патчи immer (стек патчей, ограничение 100 шагов). Схема документа - zod с версионированными миграциями (`v1` на старте, миграции пишутся сразу, чтобы старые ссылки не ломались).

2D - чистый SVG. Одна и та же сцена (`lib/render2d/scene.ts`) отдаёт React-элементы для интерфейса, строку для PNG (через `<canvas>` и `drawImage` по blob URL), вход для PDF и картинку для OG. Никакого второго рендерера для экспорта, поэтому «в экспорте выглядит иначе» физически не случается.

3D - react-three-fiber + drei, ячейки рисуются `InstancedMesh` (одна инстансированная геометрия куба на всю доску), торцевая текстура - процедурный шейдер (годичные кольца через доменное искажение шума, параметры берутся из `Species`). Чанк 3D грузится лениво по `next/dynamic`, чтобы первый экран оставался лёгким.

PDF - jsPDF + svg2pdf.js, векторно из той же SVG-сцены. Тесты - vitest, fast-check (property-тесты на инварианты изготовимости), Playwright (smoke). UI - Tailwind + shadcn/ui.

Модули и однонаправленный поток данных: `Design -> compile -> BoardModel -> {render2d, render3d, calc, export}`.

- `lib/engine` - чистый TypeScript без React и без DOM: `compile`, `applyPaint`, `splitPanel`, `validate -> Diagnostic[]`.
- `lib/species` - справочник пород (LAB, плотность, цена, усушка), 16 позиций на старте.
- `lib/calc` - раскрой, пиломатериал, отходы, себестоимость.
- `lib/generators` - шаблоны, симметрия, эволюция, photo-to-pattern.
- `lib/render2d`, `lib/render3d`, `lib/export`, `lib/persist`.

Чистота `lib/engine` не декоративная: на ней держатся и CLI, и тесты, и серверный рендер OG-картинок.

## Функциональный scope

### MVP конкурса

Редактор узора в виде сетки с двусторонней синхронизацией: пользователь красит ячейку, движок понимает, что за этим стоит. Если правка выражается изменением существующей полосы - применяется сразу. Если нет - предлагается «разветвить панель» (fork panel) с явно названной ценой: «+1 склейка, +1.2 м ясеня, +40 минут». Пользователь всегда видит, во что обходится красота.

Породы (не менее 16, включая палитру для тех, кто мыслит цветами), поворот и зеркалирование рядов и панелей, габариты доски, сохранение проекта, экспорт PNG.

Постоянно видимый complexity meter в шапке редактора: число склеек, число резов, метры пиломатериала по породам, процент отходов, себестоимость. Это же и есть ответ на критерий «можно ли изготовить настоящую доску».

Проверки реализуемости (`validate`) выдают `Diagnostic[]` трёх уровней (error, warning, info): минимальная ширина полосы (4 мм), ширина рейсмуса (330 мм по умолчанию, настраивается), припуск на строгание +3 мм на каждый срез, несовместимая усушка соседних пород (разница тангенциального коэффициента больше 1.5 процентных пункта), длина каретки/салазок, направление волокна (в торцевой доске все ряды обязаны быть торцом вверх).

### Бонусы

Генеративные узоры, библиотека из 16 параметрических шаблонов, 3D-превью, kerf, карта раскроя, пошаговая схема переклеек, расчёт пиломатериала и отходов, себестоимость, мм и дюймы, PDF-инструкция, проверка реализуемости, оптимизация раскроя (first-fit-decreasing по доскам стандартной длины), импорт изображения.

Генераторы: симметрийные группы p4m, pmm, p2; параметрические семейства (шахматка, кирпич, chevron/herringbone, хаос на синем шуме); интерактивная эволюция - 9 вариантов на экране, пользователь отмечает понравившиеся, кроссовер параметров, fitness учитывает контраст соседних ячеек, симметрию и штраф за число склеек.

### Photo-first flow

Пайплайн: изображение -> даунсемпл до 128 px по длинной стороне -> k-means в LAB на 4-6 кластеров -> отображение центроидов на реальные породы по минимальному расстоянию в LAB (с запретом повторов) -> «проекция на изготовимость»: строки пиксельной карты кластеризуются k-medoids, число медоидов задаётся слайдером «похожесть против числа склеек». Одна крайность слайдера - максимум сходства и много панелей, другая - 2-3 панели и стилизованный мотив. Результат - обычный `Design`, дальше редактируемый руками. Никакой нейросети в этом пути нет, поэтому результат детерминирован и всегда изготовим.

### Дополнительные фичи

- Etsy-пакет: генератор листинга (заголовок, 13 тегов, описание), цена из себестоимости и заданной маржи, мокап (3D-рендер на кухонном фоне).
- «Приёмка мастера»: rule-based критика проекта с характером, поверх тех же `Diagnostic[]`, но текстом живого прораба. Внешний API не нужен.
- Шаринг: сжатая ссылка + автоматическая OG-карточка через `@vercel/og`.
- Merch-генератор: узор как арт + произвольный текст с выбором из 6 шрифтов -> товары Printful.
- CLI (npm-пакет) поверх того же `lib/engine`.

## Монетизация и Stripe

Тарифы, откалиброванные по прямому конкуренту cuttingboarddesigner.app ($0.99/нед, $2.99/мес, $9.99/год) и по инструментам для Etsy ($6-30/мес):

| План | Цена | Что входит |
|---|---|---|
| Free | 0 | Редактор, 2 проекта, PNG и PDF с watermark, 2D, photo-to-pattern в 2 вариациях, 5 демо AI-картинок на устройство |
| Pro | $9/мес или $79/год | 3D, безлимит проектов, photo-to-pattern, Etsy-листинг, полный PDF, 100 AI-картинок в месяц |
| Lifetime | $99 единоразово | Всё из Pro, 300 AI-картинок суммарно, дальше по своему ключу Gemini |
| Studio | $19/мес | Всё из Pro + merch-генератор и 500 AI-картинок |

Мы намеренно дороже прямого конкурента: он рисовалка, мы считаем себестоимость и генерируем листинги, то есть окупаемся с одной проданной доски.

Реализация: Stripe Checkout (ссылки на Payment Links для простоты, webhook на Vercel serverless `app/api/stripe/webhook/route.ts`). Хранение entitlement - минимальная таблица в Supabase `licenses(email, plan, status, ai_credits_used, license_key, stripe_customer_id, created_at)`. Полноценной авторизации нет: после оплаты webhook создаёт строку и отправляет письмо с license key, пользователь вставляет ключ в настройках, приложение обменивает ключ на подписанный JWT (срок 30 дней) через `/api/license/verify` и хранит его в localStorage. Это даёт мультиустройство без пароля и без формы регистрации, что критично для конверсии.

Гейтинг двухуровневый, и мы честно признаём разницу. Серверные функции (AI-картинки через Gemini, генератор Etsy-листинга, создание draft-заказа в Printful, выдача лицензии) проверяют JWT на роуте, обойти их из браузера нельзя. Клиентские функции (photo-to-pattern, 3D, PDF) считаются в браузере, поэтому защищены мягко: без Pro результат photo-to-pattern доступен в двух вариациях вместо девяти, а PDF выходит с watermark. Технически продвинутый пользователь снимет это через devtools, и это осознанный размен: жёсткая защита потребовала бы серверного рендера и убила бы отзывчивость редактора, ради которой всё и строилось.

## Интеграции

**Printful** (выбран за качество и богатый API, Printify - запасной вариант). Аутентификация Private Token в заголовке Bearer, что позволяет пользователю вставить свой ключ в настройках. Используем Catalog API (variant ids), асинхронный Mockup Generator API (более жёсткий rate limit, поэтому очередь с polling), Order API с draft-заказами. Общий лимит 120 запросов в минуту, ставим клиентский throttle на 100. В каталоге нет деревянных торцевых досок, есть стеклянная разделочная, поэтому merch - постеры, футболки, кружки, фартуки и стеклянные доски.

**Gemini**: модель `gemini-3.1-flash-image` ($0.067 за картинку, lite-вариант $0.0336), вызов `POST /v1beta/models/{model}:generateContent`, редактирование картинки = image part + текст. Применение строго декоративное: кухонные сцены для Etsy и merch, стилизованные share-карточки. Узоры генерирует движок, а не модель, потому что от узора требуется изготовимость, а не правдоподобие.

**Credentials UX для нетехнического пользователя.** Экран «Настройки -> Интеграции», по карточке на сервис. В каждой: одно поле для ключа, кнопка «Проверить» (реальный ping в API), и пошаговая инструкция со скриншотами, где именно взять ключ (для Gemini - one-click в AI Studio, для Printful - Developers -> Private tokens, для Stripe - Developers -> API keys). Ключи пользователя хранятся в localStorage и никогда не уходят на наш сервер: запросы к Printful и Gemini идут через Vercel Edge-прокси, который получает ключ в заголовке запроса и не логирует его. Статус карточки - «не подключено / проверяю / подключено», с человеческим текстом ошибки вместо HTTP-кода.

## CLI

npm-пакет `endgrain` поверх того же `lib/engine`, публикуется из монорепозитория (workspaces). Команды: `endgrain generate --template herringbone --width 400 --length 300 --species oak,walnut,maple -o board.egb.json`, `endgrain cutlist board.egb.json --units mm`, `endgrain cost board.egb.json`, `endgrain render board.egb.json -o board.svg`, `endgrain validate board.egb.json` (ненулевой exit code при errors, что делает его пригодным для CI мастерской). Формат `.egb.json` идентичен веб-версии, файлы переносятся в обе стороны без конвертации. CLI существует не для галочки: он доказывает, что движок действительно чистый.

## Персистентность и шаринг

Три носителя одного и того же zod-кодека:

1. URL hash: `Design` -> JSON -> lz-string -> hash. Целевой размер типового проекта до 2 КБ, что укладывается в лимиты всех мессенджеров. Если после сжатия больше 8 КБ, UI предлагает сохранить файл вместо ссылки.
2. localStorage: автосохранение текущего проекта каждые 2 секунды (debounce) и список последних проектов.
3. Файл `.egb.json`: экспорт и импорт drag-and-drop, поле `schemaVersion` обязательно.

Ссылка открывается серверным роутом, который параллельно отдаёт OG-картинку через `@vercel/og`: 2D-рендер доски, название, габариты и число склеек. Ссылка в Telegram сразу показывает доску, и это и есть виральный слой.

Миграции: реестр `migrations[v] : (unknown) -> unknown`, применяются по цепочке от версии документа до текущей. Любой чтец (веб, CLI, OG-роут) использует один и тот же `parseDesign`.

## Тестирование

- vitest: unit-тесты на `compile`, `calc`, `units`, конверсию LAB, миграции.
- fast-check: property-тесты на инварианты изготовимости. Ключевые свойства: сумма длин срезов плюс kerf и trim равна длине панели с точностью 0.01 мм; `compile` тотальна (не бросает) на любом `Design`, прошедшем zod; `applyPaint` не увеличивает число склеек, если не вызван `splitPanel`; отходы неотрицательны и не превышают закупленный объём; любой `Design`, признанный `validate` без errors, имеет все полосы шире минимальной и все панели уже рейсмуса; round-trip `serialize -> parse` возвращает эквивалентный документ.
- Playwright smoke на проде: открыть шаблон, покрасить ячейку, переключиться в 3D, скачать PNG, открыть share-ссылку и убедиться, что доска совпала.
- CI на каждый push в main, main всегда деплоится, незаконченные фичи скрыты за флагами в `lib/flags.ts`.

План 7 дней: D1 движок, породы, калькуляторы, деплой каркаса; D2 SVG-редактор; D3 3D, персистентность, шаблоны; D4 генераторы, эволюция, импорт изображения; D5 экспортёры (PDF самый рискованный, fallback - HTML-страница со стилями для печати, которая через Ctrl+P даёт тот же результат); D6 виральный слой, Etsy-листинг, мобильная полировка, английская локаль; D7 примеры досок, GIF, README, буфер. Монетизация и интеграции делаются в D6 за флагами и не блокируют сдачу: если Stripe не успевает, конкурс сдаётся с `PRO_UNLOCK=1` для всех.

## Границы: что осознанно не делаем

Рекурсия панелей глубже 2 уровней. Произвольные криволинейные и инкрустационные узоры (только прямоугольная и угловая геометрия). Полноценная авторизация с паролями и OAuth. Совместное редактирование в реальном времени. Мобильное приложение (только адаптивная вёрстка). Собственное производство и логистика досок. Симуляция физики склейки и расчёт прочности. Генерация самого узора нейросетью. Поддержка Printify в первой версии. Оффлайн-режим и PWA. Расчёт стоимости работы мастера по часам (только материал плюс заданная маржа).

## Риски

Главный технический риск - PDF: связка jsPDF и svg2pdf.js капризна к шрифтам и трансформациям. Митигация заложена в план как отдельный fallback (печатная HTML-страница), решение о переключении принимается вечером D5 по факту, а не в дедлайн.

Второй риск - объём scope. Монетизация, Printful, Gemini, CLI и merch суммарно больше, чем конкурсный MVP. Митигация: жёсткий приоритет, всё сверх MVP живёт за флагами, и любая фича, не готовая к утру D7, выключается, а не доделывается.

Третий риск - качество photo-to-pattern на сложных фото. Митигация: слайдер «похожесть против склеек» превращает слабый результат в осознанный выбор пользователя, плюс в галерее примеров лежат три заведомо удачных исходника для демо.

Четвёртый риск - rate limit Printful на мокапах (жёстче общего) и стоимость Gemini при демо-нагрузке. Митигация: очередь с polling, кэш мокапов по хэшу узора, и лимит демо-картинок на устройство (5) для всех, кто не оплатил план и не ввёл собственный ключ Gemini.

Пятый риск - производительность 3D на больших досках (доска 500 × 400 мм с шагом 20 мм даёт около 500 ячеек, что немного, но при мелком шаге счёт идёт на тысячи). Митигация: `InstancedMesh` с одним draw call, ограничение сетки 4000 ячеек и предупреждение валидатора выше 2000.

Шестой риск - приватный репозиторий при требовании прислать ссылку на репозиторий. Митигация: судьям выдаётся read-доступ по их GitHub-аккаунтам, репозиторий публичным не делается.

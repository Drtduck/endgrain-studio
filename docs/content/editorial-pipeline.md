# Редакционный конвейер блога Endgrain Studio

Этот файл - рабочая инструкция для агента, который пишет статьи (запускается
ежедневной автоматизацией Orca). Выполнять сверху вниз, ничего не пропуская.

## Источники

- Бэклог тем: `docs/content/question-backlog.md`. Статусы тем: `todo`, `done <slug>`.
- Существующие статьи: `content/blog/*.mdx`, реестр `lib/blog/registry.ts`.
- Гайд по MDX и метаданным: `docs/superpowers/specs/2026-08-13-blog-seo-geo-design.md`.

## Шаги

1. Открой `docs/content/question-backlog.md`, выбери САМУЮ ВЕРХНЮЮ тему со статусом
   `todo` (бэклог отсортирован по приоритету). Проверь по реестру, что статьи на эту
   тему ещё нет.
2. Создай ветку `content/<дата>-<slug>` от main.
3. Напиши статью НА АНГЛИЙСКОМ (основной рынок: США): 900-1500 слов, структура:
   - H1 = вопрос из бэклога (как реально спрашивают);
   - первый абзац: прямой ответ на вопрос в 2-4 предложения (Answer-блок, он же
     `meta.answer` для llms.txt);
   - H2-заголовки вопросами, таблицы вместо перечислений в прозе, конкретные числа
     с условиями (породы, миллиметры и дюймы, цены в долларах);
   - один органичный блок про Endgrain Studio там, где продукт реально помогает
     (расчёт распила, материала, себестоимости, PDF), со ссылкой на студию;
   - без выдуманных фактов: числа только те, в которых уверен, либо с оговоркой.
4. Прогон по анти-ИИ чек-листу (обязателен, статья не выкладывается без него):
   - НЕТ длинного тире U+2014 нигде;
   - нет троек-перечислений ради ритма (rule of three), нет «Not X, but Y»,
     нет «Let's dive in», «In this article we will», «It's worth noting»,
     нет симметричных абзацев-близнецов, нет промо-эпитетов (game-changer,
     seamless, effortless, unlock);
   - есть минимум три конкретные детали (число, порода, инструмент) на статью;
   - есть авторская позиция хотя бы в одном месте (рекомендация с обоснованием);
   - заголовки не начинаются одинаково.
   Если что-то сработало: переписать абзац, не публиковать как есть.
5. Переведи статью на РУССКИЙ: не калька, а адекватный живой перевод (мм вместо
   дюймов в основном тексте, дюймы в скобках). Правила русского текста: без
   длинного тире, «ёлочки», без канцелярита.
6. Оформи оба файла в `content/blog/`:
   - EN: `<slug>.mdx`, `meta.lang: 'en'`;
   - RU: `<slug>-ru.mdx`, `meta.lang: 'ru'`, `translationOf: '<slug>'`;
   - у обоих: title, description (до 155 символов), answer, tags (2-4), date
     (сегодня), cover (сгенерируй через `scripts/blog-covers.mjs`, стиль как у
     существующих обложек).
7. Зарегистрируй обе статьи в `lib/blog/registry.ts`.
8. Гейты: `pnpm typecheck && pnpm lint && pnpm test` и `pnpm build`. Всё зелёное,
   иначе чинить.
9. В `docs/content/question-backlog.md` смени статус темы на `done <slug>`.
10. Коммит по-русски (`feat(blog): статья "<заголовок EN>"`), пуш ветки,
    `gh pr create` с кратким описанием и пометкой, что анти-ИИ чек-лист пройден.
    PR НЕ мержить: merge остаётся за человеком или babysitter-процессом.

## Ограничения

- Одна статья (EN+RU) за запуск. Не трогать чужие файлы, кроме перечисленных.
- Если бэклог пуст (нет `todo`): не выдумывать тему, а создать issue
  `content: бэклог пуст` и выйти.
- Если гейты падают не из-за статьи: зафиксировать в PR-описании и не мержить.
